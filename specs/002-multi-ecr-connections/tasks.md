# Tasks: Several ECR registries in one Snyk org

**Input**: Design documents from `specs/002-multi-ecr-connections/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

Generated by `/speckit-tasks` on 2026-11-24, after the plan and the read-only probe of Snyk's
closed-beta API (live checks L3, L6, L7).

**Tests**: included. Constitution Principle I requires a unit test of the delete scope in each mode,
Principle V an offline `make check`, and the spec's acceptance scenarios say what each test pins.
Within each story the tests come first and must fail before the code that makes them pass.

**Organization**: grouped by the spec's user stories, US1 to US5. US1 and US2 are both P1; US1 comes
first because every other profiles-mode path acts on a connection.

**Live checks**: L1, L4, and L8 are settled by the `profiles` e2e step in T053, run in this cloud
session with the owner's short-lived credentials (owner, 2026-11-24) or by the owner on the Mac.
Everything else runs offline.

**Judgment calls made while generating** (the owner was away; review them in `/speckit-analyze`):

1. The profiles preflight and the closed-beta call count live in `examples/sandbox/e2e.sh`, using the
   tool's own `status` output, so `examples/sandbox/harness.py` and `tests/test_harness.py` stay
   unchanged; T049 brought plan.md's source tree in line.
2. In profiles mode the tool prints `Closed-beta calls: N` to stderr at the end of each run, so the e2e
   step can add them up. It is a new line in the output contract (T016); default mode prints nothing
   new.
3. The e2e step spaces its tool runs at least 6 seconds apart, so a burst of runs stays under 10
   closed-beta calls a minute; within a run the tool paces itself by Snyk's headers.
4. The edge case "right after a disconnect" is met by the `Connection unknown` line, which says that
   a connection just disconnected can still show projects Snyk is deleting: once a connection is gone,
   the tool cannot tell its projects from any other unattributed ones.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: US1 to US5, the spec's user stories
